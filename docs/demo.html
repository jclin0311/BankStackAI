1 · Bill payment saga

A $45 electricity bill paid from a chequing account. The orchestrator holds funds synchronously and answers 202; everything after that is an event-driven saga across four services and six Kafka topics, ending in a settled payment and a balanced ledger. Click any box or topic to see the real data that flowed through it.

2 · Natural-language request through the AI layer

One sentence travels multi-agent → Ollama → MCP server → account-service and back. The caller's JWT is relayed across every hop, so the AI layer never holds more privilege than the person who asked.

Guardrail 1 · input

Every message is screened for prompt injection before the model sees it. Allowed and blocked decisions are both audited.

Guardrail 3 · output redaction

The answer is scrubbed before it leaves: UUIDs, long account numbers and confirmation tokens are masked. It audits response_redacted only when it actually changed something — this answer carried none, so nothing was masked.

AUDIT redaction rules — from ResponseRedactionService
UUID                → [redacted-id]
long account number → first4********last4
confirmation token  → [redacted-token]

3 · Two customers, one account

Both lin and john are real Auth0 users holding the same ROLE_CUSTOMER permissions, so @PreAuthorize lets them both through the door. What separates them is the customer_id claim their tokens carry, which the service compares against the account's owner. Same endpoint, same scopes — different answer.
